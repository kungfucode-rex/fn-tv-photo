# FN Photo 1.3.7 —— 现在能在电视上自己检测升级了，安装包也从 66 MB 瘦到 26 MB

昨天发过一个 1.2，这中间又改了八版。这次开新帖，把 1.2 之后的东西一次说清楚，主要是两件：**应用能在电视上自己检测并升级**，以及**安装包小了 40 MB**。

如果你没看过上一帖：FN Photo 是一个 Android TV 端的飞牛相册客户端，走的是飞牛相册自己的接口（不是把 NAS 当文件共享读），所以在电视上看到的就是相册 App 里的那份内容 —— 时间线、相册、文件夹、人脸、服务端缩略图、Live Photo 和视频都在。完全遥控器操作，免费开源、无广告无内购。

## 一、设置里多了「检测升级」

进设置页它会自己查一次，按 OK 再查一次。

查到新版本，那一行会写「有新版本 1.4.0」之类，按 OK 就开始下载，屏幕上走百分比；下完之后：

1. 先校验 SHA-256 —— 确认下下来的就是发布页上那一个文件；
2. 再校验这个 APK 的**签名证书和应用自己是不是同一把**；
3. 两个都过，才交给系统安装器，由你在电视上确认安装。

任何一步走不通，那一行都会**把原因和耗时写出来**（比如「SocketTimeoutException: failed to connect…」），并给一个手动下载地址。电视上没有控制台，这是唯一能把它读出来的地方 —— 上一版里我自己的电视就是这么把问题报给我的。

【图 1：设置页 —— 检测升级那一行】

两点说明白：

- **它只在你进设置页（或按 OK）的时候联网**，平时不联网、不上报任何东西。它会访问 Gitee 和 GitHub 的发布页去问「最新是哪个版本」—— 上一帖里写的「不连任何第三方服务器」这句话，从 1.3.2 起就不成立了，这里更正一下。没有账号体系、没有埋点，除此之外不联系任何地方。
- **两个来源同时问**：Gitee（国内）和 GitHub。我自己家的网络会把 github.com 丢进黑洞，只问 GitHub 时那一行要干等二十多秒才说「检查失败」；现在两个一起问，谁先答用谁，并取两者中更新的版本。

## 二、安装包从 66 MB 瘦到 26 MB

原来的音乐目录里有九首、共 54.5 MB —— 占了整个包的五分之四，而其中最占地方的三首恰好都是舒缓器乐（水墨兰亭 12.9 MB、云水禅心 11.5 MB、绿野仙踪 箫 10.6 MB，一共 35 MB），和幻灯片那种一张接一张的节奏其实不太搭。

现在只留四首、共 14.3 MB：

- 悦荟 - 菊次郎的夏天(钢琴版)
- Thomas Greenberg - Easy Breeze
- 唐艺 - 月亮照山川 (Live)
- 迎着风 向前冲 (万妖图录传)

那五个文件是从 APK 里**删掉**的，不是只从列表里去掉 —— 没人能选的曲子，每个下载它的人还是得为它付流量。为了这件事以后不被忘掉，代码里加了一条检查：音乐目录里只要有文件不在列表里，构建就直接失败。

【图 2：背景音乐列表，现在四首】

顺带，设置页里「幻灯片间隔」那一行去掉了：间隔在查看器的控件条里一直都能调（见下面图 3），设置里那行只是第二个入口，而它占的高度正好让整列超出 1080p 屏幕。值没有丢，从哪边改都是同一个设置。

## 三、从 1.2 以来还改了什么

- **预览原图**（1.3）：设置里三档，默认「仅用于幻灯片播放」—— 手动翻页用服务端那张 1920px 大缩略图（网格里已经下过、磁盘缓存里就有，翻页立刻出图），幻灯片才去取原图。外网看 NAS 时，这一项就是「翻页立刻出图」和「等一张多兆原图」的区别。
- **信息条会写明眼前这张是原图还是缩略图**，是缩略图时角上多一个「原图」按钮（1.3.1）：按下去按钮开始呼吸，文件由后层悄悄取回，到手原地换上去，**中间不黑屏**。这是「就这一张、现在要看全画质」，不改设置 —— 翻到下一张仍然是缩略图。

【图 3：大图 + 信息条 —— 注意「缩略图」角标和「原图」按钮】

- **翻页不再依次预览中间几张**（1.3.1）：翻页走的是指针，按右键只是把指针往前挪一格，**只有指针停下的那张会被取回来**。连按三次右键就是三个箭头、然后第 3 张；中间两张既不上屏也不下载。慢网络下这一条最明显 —— 旧实现会把每次按键都排进队列依次下载，连按十几次看起来和卡死没分别。

【图 4：翻页排队的箭头】

- **视频现在能播了（在自签证书的 NAS 上）**（1.3.1）：之前视频走系统证书信任，照片能看、视频却报 `Trust anchor for certification path not found`；现在视频流和图片走同一条路，带上访问码 cookie 和固定证书信任，拖动进度也照旧可用。**上一帖的「已知限制」里那一条可以划掉了。**
- 修掉几处「一直往后翻会卡死」的根因。
- 设置里多了一行**检测升级**，少了一行幻灯片间隔（就是上面那两件事）。

【图 5：幻灯片控件条 —— 播放 / 间隔 / 顺序 / 背景音乐】

## 四、怎么装

**附件里的 APK 就是最新版，直接下附件最省事**（25.6 MiB）。也可以从发布页下：

- Gitee（国内快，应用内升级也用这个）：`https://gitee.com/kungfu%63ode/fn-tv-photo/releases/latest`
- GitHub：`https://github.com/kungfu%63ode-rex/fn-tv-photo/releases/latest`

> 网址里的 `%63` 就是字母 c：论坛会把 `kungfu` 里的两个字母自动打码掉，写成 `%63` 就能绕开，而浏览器和服务器都会自动还原它，点开是同一个页面（实测两个站点都 302 到最新版那个 tag）。**万一链接还是打不开，直接下帖子附件就行。**

版本信息：

- 文件名 `FN-tvphoto-1.3.7.apk`，26,817,782 字节（25.6 MiB），包名 `com.kungfucode.fntvphoto`
- SHA-256：`8DA29D5A2E7354243E818ED38C1810D77C4990A8FB65CD51ED51D7AC2F876923`
- 两个站点的包逐字节相同

安装（三种任选）：

1. 拷到 U 盘插到电视上，用电视自带的文件管理器点开安装（大部分电视要先在设置里允许「未知来源应用」）；
2. 用当贝市场 / 电视助手之类的「本地安装」功能；
3. 会用 adb 的话：`adb install -r FN-tvphoto-1.3.7.apk`

首次打开填 NAS 地址，例如 `192.168.31.14:50317`（不写端口就按飞牛默认的 5667 走），再填飞牛的账号和密码。NAS 如果开了访问码，会多出一个访问码输入框。

## 五、环境要求

- Android 6.0（API 23）及以上，电视、盒子、投影都行。
- NAS 和电视在同一个局域网，相册服务已开启，账号能读到照片。
- 「文件夹」读的是相册的托管文件夹，列表是空的话，去飞牛里把目录加进去就行。
- 应用内升级需要电视能访问 Gitee 或 GitHub；不能的话那一行会说明原因并给出手动下载地址，手动装一样。

## 六、已知限制（先写在这里，省得大家踩坑）

- 只读：浏览、看图、幻灯片没问题；删除、上传、重命名、收藏都还没有。
- 大图页没有缩放和拖动。
- 飞牛相册的接口不是公开接口，官方一改就可能失效，到时候我尽量跟。
- 密码保存在 App 本地的 SharedPreferences 里（这套接口没有 refresh token 可用，只能这样），介意的别在 App 里存密码。
- 升级检测要联网（只在进设置页时），会给 Gitee / GitHub 发一次请求 —— 上一帖写的「不连任何第三方服务器」不再成立，特此更正。
- **内置音乐是四首商业录音**，随 APK 公开分发有版权顾虑；如果你要再分发，建议自己替换成可自由使用的曲目（`app/src/main/assets/music/`）。这一点上一帖就提过，这次曲子少了但性质没变。
- 从 1.2 或更早的版本升级过来是覆盖安装，设置会保留；但 1.2 之前的包名是 `com.tvphoto`，对 Android 来说是另一个应用，会各出现一个图标，装过旧的先卸载。
- **1.2 及更早的版本没有「检测升级」**，照着上一帖装了 1.2 的话不会自动提示，请直接下这一版。
