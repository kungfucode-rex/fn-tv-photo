■ 怎么发

1. 打开 docs/forum-post-fnnas-137.md，第一行「# FN Photo 1.3.7 —— …」整体填进标题栏
   （如果论坛标题栏不接受 markdown，就把「# 」去掉，只留文字）。
2. 正文从「昨天发过一个 1.2」那一行开始，到文件末尾，全选粘贴。
3. 正文里有 8 处【图 N：…】标记。插图后把那一行删掉（或者保留，看论坛习惯）。
4. 论坛如果**不认 markdown**（不少 Discuz 不认），`##` 和 `**` 会原样显示。
   真遇到这种情况，告诉我，我把同一份内容按纯文本（■ / ·）重排一份 —— 1.2 那帖就是那种排版。

■ 网址会被论坛打码，怎么处理

现象：`kungfucode` 里的两个字母被论坛自动屏蔽，`https://github.com/kungfucode` 变成
`https://github.com/kung**code`，链接就点不开了。

已经实测过的三条路（2026-10-08 实测，含大小写那条**失败**的结果）：

1. ~~改大小写~~ —— **不行**。写成 `kungFuCode` 一样被打码，说明论坛的过滤不区分大小写。
   （两个站点本身是认大小写的：`github.com/kungFuCode-rex/…` 与 `gitee.com/kungFuCode/…` 都返回
   200，`releases/latest` 也照常 302 —— 所以这条本来能用，只是被过滤挡住了。）
2. **把 c 写成 %63（当前正文用的就是这个）**：`https://github.com/kungfu%63ode-rex/fn-tv-photo`。
   HTTP 层会解码 `%63`，实测：
     · github.com/kungfu%63ode-rex/fn-tv-photo/releases/latest  → 302 到 /releases/tag/v1.3.7
     · gitee.com/kungfu%63ode/fn-tv-photo/releases/latest       → 302 到 /releases/tag/v1.3.7
     · github.com/kungfu%63ode-rex/fn-tv-photo/releases/tag/v1.3.7 → 200
   不依赖大小写，原始文本里也没有敏感串，所以过滤抓不到。
   注意：**Gitee 的 raw 文件路径不能这么写**（`…/raw/master/version.json` 会 404），
   所以只用在页面链接上，别用在直链文件上。
3. **换地址（根本解法）**：把仓库转到一个名字干净的组织，例如 `fn-photo`，地址变成
   `https://github.com/fn-photo/fn-tv-photo` 与 `https://gitee.com/fn-photo/fn-tv-photo`，
   两个都不含敏感串，以后每帖都能直接点。
   代价与风险：应用里两处硬编码的清单地址（`UpdateChecker` 的 SOURCES）、
   `tools/release-manifest.ps1` 与 `tools/publish-gitee.ps1` 的默认值、README 里的链接都要改，
   然后发一版（1.3.8）。GitHub 转移后旧地址会自动 301，老帖和现装用户的 GitHub 通道不会断；
   **Gitee 转移后旧路径是否跳转未验证**，而 Gitee 正是国内用户那条路 ——
   所以真要做，应用里应该同时留着新旧两个地址（旧的做兜底），再发 1.3.8。

另外正文里已经写了「附件里的 APK 就是最新版」——**把 25.6 MiB 的 APK 传成论坛附件**是最省事的做法：
读者不用点任何外链，网址打不打码都不影响下载。
